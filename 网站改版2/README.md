# 网站改版2 · 预览版

在「网站改版」基础上重构的整站，**目前只是预览，站点根目录一个字节都没动**。

## 和「网站改版」比，核心变了什么

### 1. 一个子板块 = 一个独立网页

| | 网站改版 | 网站改版2 |
|---|---|---|
| 页面结构 | 1 个专区 = 1 个 HTML，内含多个子板块（靠锚点跳转） | **1 个子板块 = 1 个 HTML** |
| 请假与考勤的地址 | `pages/study.html#leave` | `pages/study-leave.html` |
| 能不能单独分享 | 不能，只能分享专区页 | **能**，直接发链接 |
| 页面总数 | 9 | **58**（49 个子板块 + 9 个专区总览） |

每个子页面都带：
- 面包屑（首页 / 当前专区）
- 「上一个 / 下一个」导航（页面底部）
- 「← 返回XX专区」按钮（页面底部，位于上下页导航**下方**，居中显示）
- 专区总览页列出全部子板块卡片

### 2. 标题、简介、锚点、关键词全部写进 md

不再在构建脚本里硬编码。每个 md 开头有一段：

```markdown
---
title: 请假与考勤
desc: 线下请假条与线上出省报备两条线、天数与审批级别
zone: study
anchor: leave
order: 1
keywords: 请假, 病假, 事假, 外出报备, 出省, 销假, 考勤
---

# 请假与考勤
...正文...
```

**新增一个子板块只要两步**：
1. 建一个 md，写好 front-matter 和正文
2. 跑一次构建 —— 页面、搜索索引、首页卡片、专区总览全部自动生成

不用改任何 Python 代码。

### 3. 附件链接只写文件名

md 里写：

```markdown
[请假条申请表（空表）](<请假条申请表（空表） 电院.doc>)
```

构建时自动在 `files/` 里按文件名匹配出真实路径并改写。匹配不到会在构建日志里报警告，不会静默失败。

### 4. 卡片显示完整全称 + 一句短介绍

首页每张专区卡片上有**完整标题**（不截断，「实习就业与毕业专区」能看全）和**一句短介绍**：

| 专区 | 卡片上的短介绍 |
|---|---|
| 新生专区 | 从报到到上课 |
| 在校学习专区 | 请假、选课与成绩 |
| 奖助专区 | 奖学金与助学金 |
| 党团专区 | 党组织与团组织 |
| 生活与证件专区 | 住宿、校园卡与证明 |
| 实习就业与毕业专区 | 实习、就业到离校 |
| 文件专区 | 表格与模板下载 |
| 问题专区 | 卡住了看这里 |

短介绍写在 `tools/siteconf.py` 的 `ZONES` 表里（`brief` 字段），改完跑一次构建即可。

### 5. 每个子页面底部都有「← 返回XX专区」按钮

按钮在**页面底部**，排在「上一个 / 下一个」导航的**下方**，居中显示，与导航之间留 26px 间距。
子板块页回到所属专区，专区总览页和通知详情页回到首页。

### 6. 「上一个 / 下一个」导航

左右两张卡片，箭头做成圆形图标，靠外侧：

```
        (←) 上一个              下一个 (→)
            请假与考勤            选课与退课
```

### 7. 搜索同义词自动化

- 标题按「与 / 和 / 、 / 及 / 的」自动切分成额外关键词
  （"实习申请与外出报备" → 实习申请、外出报备）
- 真正的额外同义词（"校园卡"→一卡通、"选导"→导师双选）写在 md 的 `keywords` 里

不用再维护一张手写的 44 行同义词表。

### 8. 一键构建
双击仓库根目录的 **`更新网站.bat`**：

```
改 md → 双击 更新网站.bat → 自动打开预览页
```

构建失败会停在窗口里，不会一闪而过。

## 日常维护流程

```
1. 改 网站改版2/内容/ 下的 md
2. 双击 更新网站.bat
3. 看 _preview/index.html
4. git add -A && git commit -m "更新网站内容" && git push
```

push 之后 GitHub Actions 自动重新构建并把产物提交回仓库，GitHub Pages 随即更新。

## 迁移到主站（`deploy.py`）

`tools/deploy.py` 把「网站改版2」的产物同步到仓库根目录，**站点根目录就是线上站点**。

同步采用**先删后拷**：`pages/` `data/` `files/` `notices/` `assets/` 五个目录会先整体清空，
再复制新产物。这样上一版的旧文件不会残留在根目录变成死链或垃圾。

同步的内容：

| 源 | 目标 |
|---|---|
| `index.html` | `/index.html` |
| `pages/` | `/pages/`（并额外生成 6 个旧链接跳转页） |
| `data/` | `/data/` |
| `files/` | `/files/` |
| `notices/` | `/notices/` |
| `assets/` | `/assets/` |
| `sitemap.xml` `robots.txt` `404.html` | 根目录 |

旧链接跳转页（保留别人收藏过的链接）：

| 旧地址 | 跳到 |
|---|---|
| `pages/leave.html` | `pages/study-leave.html` |
| `pages/internship.html` | `pages/career-internship.html` |
| `pages/graduation.html` | `pages/career-degree.html` |
| `pages/other.html` | `pages/life.html` |
| `pages/notices.html` | `pages/about-disclaimer.html` |
| `pages/notice.html` | `pages/notice-2026100.html` |

**手动跑一次**（本地先看一眼效果）：

```
python 网站改版2/tools/deploy.py
```

跑之前建议先 `git status` 确认工作区干净，跑完用 `git diff` 检查根目录的变化符合预期。

CI 里的顺序是：**构建 → 链接检查 → 同步 → 提交**。任何一步失败都会中止，
不会把「半新半旧」的产物推到线上。

## front-matter 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 页面大标题，也是搜索索引的主键 |
| `desc` | | 一句话简介，显示在标题下方和专区卡片上 |
| `zone` | ✅ | 归属专区，见 `tools/siteconf.py` 里的 `ZONES` |
| `anchor` | | URL 短名，不填则自动从 title 生成 |
| `order` | | 专区内排序，小的在前，默认 999 |
| `keywords` | | 额外搜索同义词，逗号分隔 |
| `internal` | | `true` = 内部文档，不上线、不进导航、不进搜索 |
| `updated` | | 最后更新日期 |

## 这一轮补上的东西

| 项 | 说明 |
|---|---|
| `data/site-config.json` | 站点配置（GA 测量 ID、问卷星链接）。之前缺这个文件，首页反馈按钮点了没反应 |
| 问卷星入口按配置显示 | 没配或还是示例地址时自动隐藏，不再给用户一个打不开的链接 |
| JS 全部带 `?v=` 版本号 | 之前首页 6 个 JS 没带，改了不生效是常事 |
| mermaid 按需加载 | 61 个页面全引 1MB 的 CDN，现在只有 20 个真有流程图的页面引 |
| mermaid 加载失败降级 | CDN 被墙时显示文字流程，不留空白 |
| 搜索支持拼音 | `qj` / `qingjia` 都能搜到「请假」；靠 `data/pinyin-table.json`（988 字，4KB） |
| 搜索索引补齐 | 从 49 条 → 61 条（加进 9 个专区总览页 + 3 个通知页） |
| SEO | `og:` / `twitter:` / `canonical` / `keywords` 标签 + `sitemap.xml` + `robots.txt` + `404.html` |
| 无障碍 | `:focus-visible` 焦点环、「跳到正文」链接、搜索框和主题按钮的 `aria-label` |
| 打印样式 | 打印时自动去掉导航/按钮/背景色，表格与流程图完整保留，外链显示地址 |
| 减少动效 | 尊重系统「减弱动态效果」设置 |
| `deploy.py` 先删后拷 | 之前只覆盖同名文件，旧站点的死文件会残留在根目录 |
| 占位符清单自动生成 | `tools/placeholders.py` 重新生成「待填写占位清单」，不再手改 |
| GA ID 集中管理 | 从 `data/site-config.json` 读，不再硬编码在模板里 |
| 文件专区附件浏览器 | 文件专区总览页可按分类 / 格式筛选，也可搜文件名（含拼音首字母）。清单由 `data/downloads.json` 驱动，**加新附件只要放进「内容/08_文件专区/附件/」，构建一次自动出现** |
| 常见搜索词 | 首页原来的「热门搜索关键词」标着编造的搜索次数（128/96/88…），已改为不标次数的「常见搜索词」，共 39 个。**每个词都验证过在站内确实搜得到东西** |
| 站点内容统计 | 首页「数据统计」原来请求一个已挂掉的 Cloudflare Worker，永远显示「—」。改成构建时从真实文件算出的四个数字：可下载资料 28 / 流程页面 58 / 事务专区 8 / 常见问题 6。访问量请看 Google Analytics |
| 清理死代码 | 又删掉 1 个死 JS（`download-rank.js`，首页本来就没这个区块）和对应的 100 多行死 CSS |
| 修复 Pages 构建失败 | 仓库原本没有 `.nojekyll`，GitHub Pages 默认用 Jekyll 构建，会去渲染 `网站改版2/内容/` 里的 Markdown 内容源，`jekyll-relative-links` 插件改写相对链接时报错，整个部署中断、线上停留在旧版。**加 `.nojekyll` + `_config.yml`（exclude 掉源文件目录、worker/、admin/、docs/）后，本地 Jekyll 构建从 139 秒降到 0.25 秒**，发布内容也只剩该发布的 |
| 修复数据缓存 | JSON 数据文件原本不带版本号，内容更新后浏览器仍读旧缓存（首页「常见搜索词」只显示 10 个旧的）。现在每个页面注入 `window.SITE_VER`，11 处 `fetch` 统一拼 `?v=`，`make.py` 通过环境变量保证一次构建内版本号一致 |
